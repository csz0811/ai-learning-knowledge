# AI产品架构七层模型

> 做任何一个 AI 产品前，先用这个框架想清楚七个问题。
> 每个问题回答清楚，产品架构就稳了。

---

## 八层模型总览

```
┌─────────────────────────────────────┐
│  1. UI设计层   → 用户看到什么        │
├─────────────────────────────────────┤
│  2. 核心价值层  → 为什么做这个        │
├─────────────────────────────────────┤
│  3. skill层    → 系统有什么能力      │
├─────────────────────────────────────┤
│  4. 运行逻辑层  → 怎么做              │
├─────────────────────────────────────┤
│  5. 数据层     → 数据从哪来到哪去    │
├─────────────────────────────────────┤
│  6. 接口层     → 怎么通信            │
├─────────────────────────────────────┤
│  7. 安全与部署层 → 谁能用 怎么上线    │
├─────────────────────────────────────┤
│  8. 成本层     → 花钱还是省钱        │
└─────────────────────────────────────┘
```

**注：** 七层模型是标准版；第八层成本层根据产品性质决定是否需要——如果产品涉及付费 API 调用、存储费用等，加上第八层一起考虑。

---

## 第一层：UI设计层

**核心问题：用户看到什么？**

| 检查项 | 问题 |
|--------|------|
| 入口 | 用户从哪里进入？（网页/App/微信/API） |
| 专业用语 | 给这个产品起什么名字？界面上用什么词？ |
| 交互流程 | 用户第一步做什么、第二步做什么？ |
| 反馈 | 操作后用户得到什么回应？ |

**举例：**
- 入口：内部员工 → 公司内网网页
- 用语：知识库 / 智能问答 / 检索
- 流程：输入问题 → 等待回答 → 复制答案
- 反馈：回答结果 + 来源文档标注

---

## 第二层：核心价值层

**核心问题：这个产品解决了谁什么问题？**

| 检查项 | 问题 |
|--------|------|
| 目标用户 | 谁用？内部员工 / 客户 / 特定人群 |
| 痛点 | 他们现在怎么解决这个问题的？ |
| 价值 | 用了这个产品，比之前快多少 / 省钱多少 / 省力多少 |

**举例：**
- 目标用户：直播运营团队
- 痛点：每次要回答弹幕 FAQ，要去很多地方翻资料
- 价值：一个搜索框，5秒出答案，不用翻文档

---

## 第三层：skill层

**核心问题：系统需要哪些能力？**

| 检查项 | 问题 |
|--------|------|
| AI 能力 | 用什么模型？DeepSeek / GPT-4 / Claude |
| 检索能力 | RAG / 关键词 / 混合搜索 |
| 工具能力 | 查天气 / 写文件 / 发消息 |
| 记忆能力 | 多轮对话 / 长期记忆 / 无状态 |

**举例：**
- AI 能力：DeepSeek Chat（文案生成）
- 检索能力：向量数据库 RAG（知识库问答）
- 工具能力：暂无（第一个版本不做工具调用）

---

## 第四层：运行逻辑层

**核心问题：用户做一件事，系统内部怎么跑？**

| 检查项 | 问题 |
|--------|------|
| 触发条件 | 用户做了什么，系统开始工作？ |
| 处理步骤 | 第一步做什么、第二步做什么、最后做什么 |
| 异常处理 | 某个步骤失败了怎么办？ |
| 返回内容 | 用户最终看到什么？ |

**举例（知识库问答系统）：**
1. 触发：用户输入问题
2. 步骤：问题 → 向量化 → 检索向量库 → 拼 Prompt → 调 LLM → 返回回答
3. 异常：向量库空了 → 返回"暂无相关内容"；LLM 超时 → 返回"服务繁忙"
4. 返回：文字回答 + 标注来源文档

---

## 第五层：数据层

**核心问题：数据从哪来、存在哪、怎么流转？**

| 检查项 | 问题 |
|--------|------|
| 输入数据 | 用户上传 PDF / 手动录入 / 自动爬取 |
| 存储 | 向量存在哪？配置存在哪？对话历史存在哪？ |
| 流转 | 数据在系统里经过哪些处理？ |
| 生命周期 | 数据什么时候删除？用户能删除自己的数据吗？ |

**举例：**
- 输入数据：管理员上传 PDF 到指定文件夹
- 存储：向量 → ChromaDB；配置 → JSON；对话历史 → SQLite
- 流转：PDF → PyMuPDF 读取 → 切块 → Embedding → ChromaDB
- 生命周期：文档管理员可删除；对话历史保留30天

---

## 第六层：接口层

**核心问题：系统怎么对外通信？**

| 检查项 | 问题 |
|--------|------|
| 协议 | HTTP REST API / WebSocket / GraphQL |
| 接口设计 | 有哪些接口？每个接口输入输出是什么？ |
| 限流 | 每个用户每分钟能调多少次？超限怎么办？ |
| 文档 | 有没有 API 文档？有没有 /docs 可调试？ |

**举例：**
- 协议：FastAPI HTTP REST
- 核心接口：`POST /ask` {question} → {answer, sources}
- 限流：未登录用户 10次/分钟；已登录用户 100次/分钟
- 文档：自动生成 /docs，Swagger UI 可调试

---

## 第七层：安全与部署层

**核心问题：谁能用？代码怎么上线？**

| 检查项 | 问题 |
|--------|------|
| 鉴权 | 谁可以调用这个系统？API Key / 账号密码 / 无限制 |
| 数据安全 | 传输加密了吗？日志里会泄露敏感信息吗？ |
| 部署方式 | Docker / 直接运行 / 云函数 |
| 运行环境 | Python 3.11 / Node / 其他 |
| 扩展性 | 并发撑不住时，怎么扩展？ |

**举例：**
- 鉴权：API Key，每个部门一个 Key，可撤销
- 数据安全：HTTPS 传输；日志脱敏（问题不存，只存回答）
- 部署：Docker 镜像部署到 Zeabur
- 扩展性：先看 Zeabur 免费额度，不够再换付费方案

---

## 第八层：成本层（可选）

**核心问题：跑这个产品要花多少钱？**

| 检查项 | 问题 |
|--------|------|
| LLM 费用 | 每次调用多少钱？免费额度够用吗？ |
| 存储费用 | 向量数据库 / 文件存储 多少钱/月 |
| 流量费用 | 带宽 / API 调用次数 |
| 人力成本 | 开发时间 / 维护时间 |

**举例：**
- DeepSeek：每月一定量免费，超出按 token 计费
- ChromaDB（本地）：免费
- Zeabur：免费额度内够用
- 预计成本：$0 ~ $20/月

---

## 使用方法

1. **开始新项目前**：七个问题全部过一遍，写清楚
2. **跟 AI 沟通前**：把每层结论整理成文字，发给 AI
3. **写文档时**：每层结论就是产品设计文档的一节
