# 用户工作方法与合作偏好观察

> 用途：小舟/Codex 接手任何项目前第一份读——理解「怎么和思之协作」，不只是理解技术。
> 创建：2026-08-24（W12-D1，用户提出「留意我的工作方法以及之后怎么合作」）
> 状态：持续补充中（每次项目过程发现新方法就追加）

## 一、为什么有这份文件
当前 W12 FAQ 项目 + 8/22 以来的治理工作，本质是**搭「思之+小舟+Codex+QClaw」协作的操作系统**，不只是交付一个 FAQ bot。
- 目的1：交付 FAQ bot（产品）
- 目的2：建可复用模板（业务背景包 / 资产卡 / 周总+项目衔接 / 质检机制）
- 目的3：捕获项目过程中真实出现的问题 + 解决方式 → 未来接手者的「少走弯路包」
本文件服务目的3的「人」维度：记录思之怎么工作、怎么和他协作。

## 二、已观察到的工作方法（带事实）
1. **直接不绕弯**：分段表达，用「但是」补真实想法，用「这个是不是」确认理解（见 USER.md）。不寒暄、不铺垫。
2. **高决策密度 + 延迟满足**：8/22 一个时段内对 5 个外部知识点收3拒1拍板1，不收 Vibe Coding 课程（过早优化），聚焦当前目标。
3. **敢连续纠正 AI**：8/22 连续多轮纠正 QClaw 的假判断/假认同/工程师视角，不附和、不因为「AI 说对」就放过。
4. **架构 / 系统思维**：自己把协作框架从 v1.2 推到 v1.4（加论证式/事实反馈），再到 v1.5（加防失效机制），治理前置而非事后补。
5. **产品 / 创业者视角**：判断标准是「客户愿意付费」，不是「功能跑通」；前端 / 审美是交付必需品不是加分项。
6. **元认知强**：8/22 主动质疑 QClaw 记忆系统底层逻辑，提出「AI 在上下文窗口运行，MEMORY 是对抗外部记忆」——这是用户教 AI 的底层认知。
7. **深度思考习惯**：遇到大问题时说「我需要深度思考一下」，不急着要答案。
8. **凌晨连轴高投入**：学习节奏 03:00-09:00，单次会话可连续 4-8 小时高密度。

## 三、已验证的合作原则（怎么和他协作）
- 给完整背景：他是创业者视角，模糊需求得模糊判断
- 论证式沟通：任何建议带结论 + 原因 + 利好 + 代价
- 遇到不懂领域亮出来，不假装懂也不全盘接受
- 所有知识库改动附说明（小舟 W17 进场能追溯「为什么变」）
- 被纠正后走三步 gate：复述理解 / 影响面 / 异议检查
- 事实反馈：有具体事实才夸，和多数人持平不夸，禁止盲目吹捧
