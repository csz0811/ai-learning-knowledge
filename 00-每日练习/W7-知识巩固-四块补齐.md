## ① temperature + max_tokens

### temperature（采样随机度）
- 范围一般 0~2，常用 0~1
- **0 = 最确定**：同样输入每次输出几乎一样 → 适合代码、翻译、事实问答、分类
- **高（0.8~1.2+）= 更跳更有创意** → 适合写诗、文案、脑暴、起名
- 口诀：**「要准用低，要活用高」**
- 你项目文案用 `0.8`（要创意但别太飞）

### max_tokens（单次回复上限）
- 限制模型这次最多吐多少 token（≈字数）
- 三个作用：① 控成本防烧钱 ② 防超时 ③ 控输出长度
- 你项目用 `800`

## ② 结构化 Prompt 优化 API 输出

### 两个层次
- **L1 文字约束**：prompt 里写「请用 JSON 返回，字段：标题/正文/标签」→ 模型尽量遵守，不保证
- **L2 JSON 模式**：`response_format={"type":"json_object"}` → 强制合法 JSON（DeepSeek / OpenAI 都支持）
- 配合 `json.loads()` 解析；配合 schema 约束字段

### Schema 是什么
- 你定义的「模型输出结构」= 字段名 + 每个字段的含义/格式
- 你项目 `CONTENT_TYPES` 每个 prompt 末尾都写了 schema（例：小红书 = 标题/正文/标签）

### 坑（必背）
- JSON 不允许注释（别写 `//` 或 `#`）
- 字段名要固定，模型输出才稳定
- 解析务必 `try/except json.JSONDecodeError`

## ③ 429 / 401 / 400 错误码

| 码 | 含义 | 常见原因 | 第一步排查 |
|----|------|---------|-----------|
| 429 | 限速 / 配额满 | 请求太频繁；余额/配额耗尽 | 降频；查余额；退避重试 |
| 401 | 认证失败 | Key 错/过期/未传；环境变量名错 | 查 Key 是否正确、是否过期、变量名 |
| 400 | 请求无效 | 参数错；JSON 格式错；缺必填 | 查请求体 / 参数 / schema |

### 你项目的防护现状（generate 的 try/except）
- ✅ **能挡 429**：瞬时限流重试有用，会恢复
- ⚠️ **挡不住 401**：密钥错，重试一万次也失败 → 应直接报错而非死循环
- ⚠️ **挡不住持久 400**：schema/格式错，重试也没用 → 需改 prompt/请求体

### 429 正确重试策略
- ❌ 不要 `while` 死循环无间隔重试（会雪崩、更被限速）
- ✅ 指数退避（等 1s→2s→4s）+ 最大次数 + 限流后停止

## ④ Streamlit 基础（W8 新课）

### 是什么
- 用**纯 Python** 写网页 UI 的库，几行代码出交互页面，不用懂 HTML/JS
- 价值：把命令行程序包成网页 = 你创业方向（提示词→脚本→闭环）第一步

### 核心组件（记住这几个就够起步）
```python
st.title("标题")                 # 页面大标题
st.text_input("标签", "默认值")   # 文本输入框，返回字符串
st.selectbox("标签", options)     # 下拉选择，返回选项
st.button("按钮")                 # 点了返回 True
st.write(变量)                   # 显示任意内容
st.json(字典)                    # 漂亮显示 JSON
st.error("出错")                 # 红色错误提示
st.spinner("...")                # 加载中转圈
```

### 怎么跑
```bash
source venv/bin/activate
pip install streamlit
streamlit run streamlit_app.py    # 自动开浏览器 localhost:8501
```
