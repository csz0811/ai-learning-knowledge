# Vibe Coding 工作流

> 一种新的 AI 编程范式，让 AI 成为真正的执行者。
> 核心：从"我写代码"变成"我说需求，AI 写代码，我来审查"。

---

## 一、什么是 Vibe Coding

**提出者：** Andrej Karpathy（前特斯拉 AI 负责人、OpenAI 联合创始人）
**提出时间：** 2025 年 2 月

**原话：**
> "这不太算是写程序——我只是说出需求，运行它，然后复制粘贴，它大多能工作。"

**核心理念：**
- 开发者不再逐行手写代码
- 用自然语言向 AI 描述需求
- AI 自动生成可运行的程序代码
- 开发者角色从"代码作者"转变为"需求策划者 + 效果验证者"

---

## 二、它和传统编程的区别

| 维度   | 传统编程     | Vibe Coding  |
| ---- | -------- | ------------ |
| 输入   | 写代码      | 说需求          |
| 执行者  | 人        | AI           |
| 角色   | 码农       | 导演/审查员       |
| 核心能力 | 写代码语法    | 描述需求 + 判断对错  |
| 反馈闭环 | 编译-调试-修改 | 描述-运行-反馈-再描述 |

---

## 三、Vibe Coding 的六层工具栈

> 让 AI 不乱的关键：上下文管理 + 知识沉淀

| 层级           | 作用            | 核心问题           |
| ------------ | ------------- | -------------- |
| **1. 代码认知层** | AI 能读懂现有代码结构  | AI 怎么知道项目里有什么？ |
| **2. 项目骨架层** | 项目状态不丢，上下文可沉淀 | 每次开新窗口信息还完整吗？  |
| **3. 需求发散层** | 把模糊想法挖清楚      | 你知道自己真正想要什么吗？  |
| **4. 方案收敛层** | 把需求变成可执行的方案   | 方案完整吗？有没有漏洞？   |
| **5. 开发执行层** | AI 实际生成代码     | AI 写出来的对不对？    |
| **6. 质量验收层** | 测试 + 人工审查     | 交付物能不能用？       |

## 五、Vibe Coding 的典型工作流

```
1. 明确意图
   → 用自然语言描述需求，不要想语法和变量名
   → "帮我做一个网页，用户输入城市名就能显示天气。"

2. AI 生成代码
   → 不需要逐行读，看整体结果
   → 运行试试看

3. 审查和反馈
   → 结果不对，直接说哪里不对
   → "温度单位改成摄氏度，图标换成太阳。"

4. 迭代直到满意
   → 整个过程是一条对话流，不是孤立的问答
   → 改 bug、加功能、写测试，全在同一个对话里完成
```

## 六、Vibe Coding 的常见误区

| 误区          | 真相                         |
| ----------- | -------------------------- |
| "AI 能理解一切"  | AI 需要清晰的上下文，模糊需求 = 模糊结果    |
| "我不需要懂代码"   | 你需要能判断对错，否则无法审查 AI 输出      |
| "一次说清楚就好"   | Vibe Coding 的精髓是迭代，不需要一次到位 |
| "AI 写的不用审查" | 你是导演，不是观众；不审查 = 不知道在做什么    |
