# 产品思维与 AI 协作框架（2026-08-19）

> 来源：与 QClaw 沟通后梳理。适用：用 AI 做真实项目（如朋友直播工具）时，练产品思维 / 架构 / 可落地、并与 AI 高效协作。

## 一、产品思维：从"做个 AI"到"解决一个人的一个疼"
- 公式：真实的人 + 真实的疼 + 最小能缓解的那一下。
- 动手前先写一页**产品定义**：①用户是谁 ②疼在哪 ③最小可用 ④怎么算成功（可量化指标）。
- 反例："做个智能客服" → 正例："主播下播整理 QA 花 1h，我做工具让她 10min 搞定"。

## 二、产品架构：每个项目 = 一张管道图
- 架构 = 输入 → AI 处理 → 输出 → 人怎么用 / 反馈。
- 写码前先画流程图，说清：上下文从哪来(RAG) / 模型在哪 / 人在哪接手 / AI 错了怎么办(兜底)。

## 三、可落地：验收 = "朋友真用了说省事"，不是"代码跑通"
- 落地清单：部署公网能跑 / 错误处理+边界 / 成本清醒 / 数据安全 / 早交付真用户(丑 v1 先给用)。
- 反例：玩具 demo（只在本机跑、没真用户）= 没落地。

## 四、怎么和 AI 沟通（把 7 步法 + Prompt 工程搬到"管 AI 当队友"）
1. 先给上下文（业务背景包 / 本次目标），别假设它懂。
2. 描述架构不是甩需求（给图，别说"做个 X"）。
3. 定接口和验收（输入/输出格式、怎么算完成）。
4. 小步验证（做一个 → 跑 → 看输出 → 再下一个）。
5. 先定"完成"再写码（开工前说清验收标准）。

## 五、每天能练的闭环
定义(1页) → 画图(架构) → 备上下文包 → 小步建(每步验证) → 交付真用户 → 量指标 → 回流配方卡

## 支撑（知识库怎么配合）
- 业务背景包 = 持久上下文 ｜ 配方卡 = 可复用架构模式 ｜ 项目库 = 真实交付+复盘 ｜ 方法论 = 思维框架
