# Prompt 模板库（W5–W6 沉淀）

> [!tip] 用途
> 把学过的 Prompt 工程技能沉淀为可直接复用的模板。
> 覆盖：角色设定 · Few-shot · CoT · Markdown 输出 · JSON Schema 输出
> 用法：复制「完整结构」→ 替换 「占位符」 → 按需删改 → 直接使用

tags: #prompt #json #模板库

## 模板 1 · 角色设定模板
**适用场景**：需要模型扮演特定身份/专家输出（写文案、做分析、答专业问题）

**完整结构**
```
你是一名「角色，要具体」，擅长「核心能力」。
请「任务」。
要求：
- 「约束1，可量化」
- 「约束2」
「输出格式：Markdown ## 分模块 / JSON Schema，按需」
```

**关键技巧**
- 角色要具体："资深电商文案专家（10年经验）" 优于 "你是一个助手"
- 约束要可量化（字数 / 必须含某词 / 风格）

**坑点**
- 角色太泛 → 输出没特色
- 约束模糊（如"写得好一点"）→ 结果不可控

## 模板 2 · Few-shot 示例引导模板
**适用场景**：需要固定格式 / 风格 / 分类标准（评论分类、特定文体、格式转换）

**完整结构**
```
你是一名「角色」。
任务：「任务描述」。
示例（输入→输出配对，高质量、有代表性）：
输入：「示例输入1」
输出：「示例输出1」
输入：「示例输入2」
输出：「示例输出2」

新任务：
输入：「真实输入」
输出：
```

**关键技巧**
- 示例必须是「输入→输出」配对，不是只列要求
- 示例要高质量、覆盖边界情况
- 真实新输入必须放最后，让模型续写

**坑点**
- 只写要求不给示例 → 模型不知具体格式
- 示例质量差 / 不典型 → 输出跑偏
- 忘记"新输入放最后" → 模型不知要处理哪条

## 模板 3 · CoT 分步推理模板
**适用场景**：多步计算、逻辑推理、复杂决策、需要可解释

**完整结构**
```
你是一名「角色」。
请「任务」。
要求：
- 请一步一步思考（Let's think step by step）
- 先展示完整推理过程，再给最终答案
输出结构：
## 推理过程
（逐步推导）
## 最终答案
（结论）
```

**关键技巧**
- 必须加触发句"请一步一步思考" / "Let's think step by step"
- 价值：显式推理 → 更准确、可让用户核验

**坑点**
- 没加触发句 → 模型直接跳答案，易错且不可解释
- 复杂题直接问 → 准确率下降

## 模板 4 · Markdown 分模块排版模板
**适用场景**：生成给人看的排版内容（商品详情页、报告、笔记）

**完整结构**
```
你是一名「角色」。
请根据「输入」生成「内容」，用 Markdown 的 ## 分模块输出：
## 「模块1」
## 「模块2」
## 「模块3」
要求：
- 风格：「风格」
- 每模块「字数 / 句式」要求
- 若信息缺失，先列出缺失项并提示用户补充
```

**关键技巧**
- 直接在 Prompt 里说"用 ## 分模块 / 用表格 / 用列表"
- 表格写法：表头 `| 列 |` → 分隔行 `| --- |` → 数据行 `| 数据 |`

**坑点**
- 表格分隔线用 `---` 不是 `#`（`#` 是一级标题）
- Markdown 与 JSON 别混用：要么排版给人看，要么纯数据给程序

## 模板 5 · JSON Schema 结构化输出模板
**适用场景**：输出给程序读取 / 解析（情感分析、信息提取、分类打标）

**完整结构**
```
你是一名「角色」。
请对「输入」做「分析」，严格按以下 JSON Schema 输出，只输出 JSON 不要解释：
{
  "type": "object",
  "properties": {
    "「字段1」": {"type": "string", "description": "说明"},
    "「字段2」": {"type": "number", "enum": ["值A", "值B"]}
  },
  "required": ["「必填字段」"],
  "additionalProperties": false
}

# 调用
response_format = {"type": "json_schema", "json_schema": {"name": "x", "schema": schema}}
# 解析
data = json.loads(response.choices[0].message.content)
```

**关键技巧**
- Schema 字段 = 模型「输出」的结果，不是输入
- enum 限定值范围、required 标必填、additionalProperties:false 防多塞

**坑点**
- Schema 写成输入信息（如把原文写进字段）→ 错了！字段是模型算出的结果
- JSON 不允许注释（别写 ← 说明）
- response_format 用 json_schema 两层，不是 json_object

## 速查表
| 模板 | 选它当… |
|------|---------|
| 角色设定 | 要特定身份 / 专家口吻 |

| CoT | 要推理 / 计算 / 可解释 |
| Markdown | 给人看的排版内容 |
| JSON Schema | 给程序读的结构化数据 |
