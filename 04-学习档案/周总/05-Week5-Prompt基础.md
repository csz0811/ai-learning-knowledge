# Week 5 · AI基础 + 基础 Prompt

tags: #W5 #阶段2 #工具

## 学习目标
- 理解 LLM / Transformer / Token
- 掌握角色设定、角色/Few-shot/CoT 三招

## 核心知识点
- LLM 本质：预测下一个 token，有幻觉、不擅长精确计算
- Token：英文≈4字符/1Token；中文1字≈0.6~1 Token；上下文窗口超限=截断/报错（非欠费）
- 角色设定三要素 = 角色 + 任务 + 约束
- Few-shot = 输入→输出示例 + 新输入放最后
- CoT 触发句 = "Let's think step by step"

## 我的易错点（来自测评）
- Transformer 拼写错（Tansformer 漏 r）→ 正式作业写错扣规范分
- Token 换算拍脑袋（英文"单词"误判）、上下文窗口超限≠欠费
- 填角色三要素把"要求"当要素、Few-shot 未答出"输入→输出"结构
- CoT 填3写"STEP STEP"不规范；填4漏"显式/验证"

### 核心概念深层理解

#### LLM 本质：预测下一个 token
```
输入："今天天气"
LLM 内部：计算下一个 token 的概率分布
输出："很" → "好" → "。"（逐字生成）
```
**两个核心局限**：
- 幻觉：训练数据里没有的信息会"编"
- 不擅长精确计算：数学/代码需要工具辅助

#### Token 计费对照表
| 文本 | Token 数（估算） |
|:---|:---|
| 1 个英文字符 | ~0.25 token |
| 4 个英文字母 | ~1 token |
| 1 个中文字 | ~0.6~1 token |
| 1 句中文（10字） | ~6~10 token |

**上下文窗口超限**：不是欠费，是**截断或报错**

#### Prompt 三剑客（对比表）
| 技巧 | 结构 | 适用场景 |
|:---|:---|:---|
| 角色设定 | 角色+任务+约束 | 固定风格输出 |
| Few-shot | 任务说明+示例(输入→输出)+新输入 | 格式规范任务 |
| CoT | 触发句+"Let's think step by step" | 多步推理/计算 |

#### 角色设定 Prompt 模板
```python
prompt = f"""
你是一个专业的小红书文案写手。
任务：为目标受众写一篇产品种草文案
要求：
- 字数控制在300字以内
- 包含emoji增加趣味性
- 最后加3个话题标签

目标受众：{audience}
产品：{product}
"""
```

#### Few-shot 完整结构
```python
prompt = f"""
把下面的商品评论分类为「正面」「负面」或「中性」。

示例1：
输入："这个咖啡太好喝了，每天早上必备！"
输出：正面

示例2：
输入："等了半个月才到，包装都破了。"
输出：负面

现在分类：
输入："{new_comment}"
输出：
"""
```
**新输入放最后**——这是最容易漏的一步

### W5 知识在 RAG/Agent 体系中的潜在应用
| W5 知识 | RAG/Agent 应用 |
|:---|:---|
| 角色设定 | RAG 回答时的系统 Prompt（"你是一个基于文档回答的助手"） |
| Few-shot | 让 LLM 按指定格式输出检索结果摘要 |
| CoT | Agent 规划下一步行动时的推理链 |
| Prompt 优化五要素 | 调试 RAG 检索质量的核心工具 |

### 最重要的踩坑教训
1. **Transformer 拼写**：必须带 `r`，写成 `Tansformer` 会扣规范分
2. **上下文窗口超限 ≠ 欠费**：是数据被截断，表现是 LLM"忘了"前面的内容
3. **Few-shot 新输入必须放最后**：放在中间会被当成示例的一部分，导致模型不知道真正要回答什么

## 一、LLM 基础概念

- [ ] LLM = **大语言模型**（Large Language Model）
- [ ] LLM 的本质：**预测下一个 token**（下一个最可能的词/字）
- [ ] LLM 的两个局限：有幻觉（会编造不真实信息）/ 不擅长精确计算
- [ ] 能说出至少 2 个 LLM 例子（ChatGPT、Claude、国产大模型）
- [ ] **Transformer** 的中文拼写（容易漏 `r`）

---

## 二、Token 与计费

- [ ] Token ≈ 4 个英文字符 / 1 个中文字 ≈ 0.6~1 token
- [ ] 上下文窗口 = 模型一次能处理的**最大 token 数**（超限会截断或报错）
- [ ] 超出上下文窗口 ≠ 欠费，是**截断或报错**（不是扣钱）
- [ ] 中英文 token 消耗差异要**实测**，不能靠想当然

---

## 三、角色设定 Prompt（W5 核心模板）

- [ ] 三要素：**角色 + 任务 + 约束**（缺一不可）
- [ ] 示例不是「角色要素」，是「Few-shot 技巧」
- [ ] 能写出完整的角色设定 Prompt（看到场景能自己写出来）

---

## 四、Few-shot（W5 核心模板）

- [ ] 结构：**任务说明 + 示例(输入→输出) + 新输入放最后**
- [ ] 示例要**高质量/有代表性**，不是随便一个简单例子
- [ ] 「新输入放最后」容易被漏掉——一定要检查
- [ ] 能写出完整的 Few-shot Prompt

---

## 五、Chain-of-Thought 思维链

- [ ] 经典触发句：**`"Let's think step by step"`**
- [ ] CoT 价值：让模型**显式展示推理过程** → 更准确、更可验证
- [ ] 适合场景：**多步推理**、**复杂计算**、**需要解释**的任务
- [ ] 能写出带触发句的完整 CoT Prompt

---

## 六、Prompt 优化实战

- [ ] Prompt 优化 Checklist 五要素：**角色 / 任务 / 要求 / 实例 / 约束**
- [ ] 实例应给「**输入 → 输出**」示例，不能只列要求
- [ ] 原始 Prompt（不加技巧版本）作为对照基准，先写基准再优化
- [ ] 能对一条 Prompt 进行优化并说明理由
