## 本课四件套

### ① chunk_size：每块多少字符
- 太大（1000+）：向量"稀释"，检索时关键词被淹没
- 太小（50-）：语义割裂，一句话被拦腰切断
- 经验值：短问答/FAQ → 200，通用文档 → 500，长文章 → 1000

### ② overlap：相邻块重叠多少字符
- 目的：防止"刚好在切割处的内容"丢失
- 常用值：chunk_size 的 10-20%（如 500 就 overlap 50-100）

### ③ 核心公式
```
step = chunk_size - overlap
```
每切一块，下一块从 `当前位置 + step` 开始，而不是跳到块末尾。

### ④ 切块的核心矛盾
块太大 → 检索不精准；块太小 → 语义割裂。没有标准答案，看文档类型。

## 🧠 知识整合（文本切块核心）

### 切块在 RAG 中的位置
切块 = **Retrieval 前处理**
- 文档 → 切块 → 向量化 → 存入向量库 → 用户查询时检索
- 切块质量直接影响检索效果：太大稀释，太小割裂

### 切块三参数
| 参数           | 含义      | 经验值                          |
| :----------- | :------ | :--------------------------- |
| `chunk_size` | 每块多少字符  | 短问答200，通用500，长文1000          |
| `overlap`    | 相邻块重叠多少 | chunk_size 的 10-20%          |
| `step`       | 下一起始位置  | `chunk_size - overlap`（核心公式） |

### 切块的核心矛盾
| 问题 | 原因 | 后果 |
|:---|:---|:---|
| 块太大（1000+） | 向量"稀释" | 检索时关键词被淹没，不精准 |
| 块太小（50-） | 语义割裂 | "人工智能"被切成"人工"+"智能"，丢失完整语义 |
| overlap=0 | 无重叠保险 | 刚好在切割处的内容丢失，"人工智能"拦腰切断 |

### 验证重叠是否生效
```python
overlap = 10  # 重叠10个字符
# 块1末尾 overlap 个字 = 块2开头 overlap 个字 → 重叠生效
chunks[0][-overlap:] == chunks[1][:overlap]  # True = 重叠正常
```

### 切块策略选择
| 场景 | 推荐 chunk_size | 推荐 overlap |
|:---|:---|:---|
| 短问答/FAQ | 200 | 20-40 |
| 通用文档 | 500 | 50-100 |
| 长篇文章 | 1000 | 100-200 |
| 代码文档 | 按函数/类自然切分 | 20-50 |
