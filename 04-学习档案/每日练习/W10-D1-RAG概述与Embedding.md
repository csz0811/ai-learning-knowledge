## 本课四件套

### ① RAG 是什么
- **RAG = Retrieval-Augmented Generation（检索增强生成）**
- 普通 LLM：`问题 → LLM → 答案`（靠模型记忆，易编）
- RAG：`问题 → 检索器(向量库) → 相关片段 → LLM(问题+片段) → 答案`

### ② 为什么要用 RAG（三痛点）
- **幻觉**：没见过的知识会编 → 检索给"参考资料"，照着答不乱编
- **知识截止**：训练数据有截止日，新信息不知道 → 能接私有/最新文档
- **私有数据**：公司内部文档、个人笔记不能训练进模型，但能放向量库随时检索

### ③ Embedding 原理（RAG 的"检索"靠它）
- 文本 → 一串数字向量（如 1536 维）；语义相近 → 向量空间距离近
- **余弦相似度**衡量两段多"像"：问题向量 vs 库里每段向量，取最近的 top-k
- 向量检索懂语义（"苹果公司"能搜到"iPhone 制造商"），胜过关键词匹配

### ④ RAG 完整流程
```
用户提问
  → Embedding 问题 → 向量
  → 向量库算余弦相似度 → 取 top-k 相关片段（Retrieval 检索）
  → 问题+片段拼成 Prompt（Augment 增强）
  → LLM 生成答案（Generate 生成）
```

## 学员作业（已提交 + 已点评）

**原回答**：
> "加了检索能更大程度的减少大模型的幻觉，因为有了检索库会比较准确，大模型会根据你的检索库里的内容输出语义最相近的内容来回答"

**评分（概念题 4 维）**：准确性 ⚠️（核心点对=减幻觉，但混淆检索器/LLM 职责）／完整性 中（漏 top-k→LLM 生成）／表达 通顺／应用 ✅（能联系减幻觉）

**纠正要点**：
- ❌ "大模型输出语义最相近的内容" —— 找"最相近"是**检索器（Embedding+向量库）**干的，在 LLM 出场前完成（捞 top-k 段）
- ✅ LLM 的活儿是**读懂 top-k 片段、用自己的话生成答案**（综合/归纳/引用），不是"输出最相近的内容"
- 区分意义：RAG = 两个独立组件——检索器负责"找"，LLM 负责"答"。以后代码分别调"向量库检索"和"DeepSeek 生成"，搞混就写串

**准确版参考**：
> 直接问 LLM，它只能靠训练记忆自由生成，容易编造。加了检索后，系统先从向量库找出和问题最相关的真实资料（top-k 片段），再让 LLM 基于这些资料组织答案。答案被"锚定"在真实文档上，所以更准、更少幻觉。

**流程图补全**：原图 `embedding→相似度→生成` 缺两步 → 完整：`提问 → Embedding → 向量库检索 top-k → 拼 Prompt → LLM 生成`

### RAG 的本质：给 LLM 配一个"实时资料库"
普通 LLM = `问题 → LLM → 答案`（靠记忆，容易编）
RAG = `问题 → 检索(向量库) → 相关片段 → LLM → 答案`（有据可查，更准）

### RAG 解决的三个问题
| 问题 | 表现 | RAG 如何解决 |
|:---|:---|:---|
| 幻觉 | LLM 瞎编 | 答案锚定在真实文档上 |
| 知识截止 | 新信息不知道 | 接私有/最新文档 |
| 私有数据 | 内部文档不能喂给模型 | 存入向量库随时检索 |

### Embedding = 把文本变成数字
- 文本 → 一串数字（向量，如 384/1536 维）
- 语义相近 → 向量空间距离近
- 余弦相似度：衡量两段文本"有多像"（值越大越相似）
- 关键优势：**懂语义**，"苹果公司"能搜到"iPhone 制造商"

### 完整 RAG 流程
```
用户提问
  ↓ Embedding 问题 → 向量
  ↓ 向量库算余弦相似度 → 取 top-k 相关片段（Retrieval 检索）
  ↓ 问题 + 片段拼成 Prompt（Augment 增强）
  ↓ LLM 生成答案（Generate 生成）
```

### RAG vs 关键词搜索
| | 关键词搜索 | 向量检索（Embedding） |
|:---|:---|:---|
| 原理 | 字符串匹配 | 语义向量距离 |
| 查"苹果公司" | 只能匹配"苹果公司" | 匹配"iPhone 制造商" |
| 同义词 | 查不到 | 理解语义，能查到 |
