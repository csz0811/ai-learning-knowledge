- 解决的问题：多人共用一个账本时的「对账、营收开销图表、投资股份占比、账变追溯」
- 核心诉求：4 账号分权限登录、手机随时记一笔、图表看占比和趋势、账变可追溯

## 三、核心功能

- 登录鉴权：JWT + 图片验证码（SVG 生成，防重放）+ 首次初始化（无默认账号）
- 营收：金额/日期/账号/平台/提现，账号平台可预先添加、记账时下拉选择
- 开销：金额/日期/类别（7 类默认，可自定义）
- 投资：投资人 + 投资费用（费用项可自定义，占比自动算）
- 图表：营收趋势（日/周/月）、开销类别占比、投资费用占比、股份占比、股东利润
- 账变记录：每次增删改自动留痕（谁/何时/做了什么），不可删改
- 权限：admin 可增删改，viewer 只读（写操作 403 拒绝）
- 字典管理：平台/账号/类别可增删改，支持「停用」（软删除）
- 分页 + 时间筛选：营收/开销/账变列表可筛时间、分页（10/20/30/50/100）

## 四、关键设计决策（🔴 重点知识）

1. **🔴 金额用「分」（整数）存储，不用「元」** —— 财务铁律。浮点数算钱有 0.1+0.2≠0.3 的误差，对账就对不上。展示时再 `÷100` 格式化成元。
2. **🔴 字典「软删除」而非物理删除** —— 有历史记录的类别/平台/账号禁止删除，只允许「停用」。停用后历史记录仍保留并标注「（已停用）」，保护历史账目不被抽掉。
3. **🔴 账变记录（审计日志）不可删改** —— 4 人共用账本，光「对得上」不够，还要「查得到是谁动的」。
4. **🔴 DB 路径用 `os.path.abspath(__file__)` 固定** —— 相对路径 `finance.db` 会随启动时的工作目录乱跑（曾建到 `E:\workbuddy_data\finance.db` 导致删库删错位置）。
5. **🔴 无默认账号，首次初始化** —— 不预置 `admin/admin123`，避免谁都能登管理员；第一次打开由用户自设管理员。
6. **🔴 验证码 + 防重放** —— 登录加图片验证码（纯 SVG，零依赖），验证码一次性、5 分钟过期，防暴力破解。
7. **🔴 掌握边界不外泄给执行者** —— 思之的掌握边界是小舟的职责，不写进给 Codex 的提示词（Codex 按完整产品标准交付）。

## 五、业务口径（本项目特有，非通用）

- **营收分两块**：平台账户余额（营收 − 提现）＋ 微信营收（微信平台营收 + 各平台提现）
- **提现 = 钱从平台转到微信**，平台余额自动扣除提现金额
- **利润以「微信到账」为准**，不是平台流水
- **股份自动算**：管理股固定 10%（思之技术股，不投钱）；其余 90% 按「已入股 + 未入股金额」自动分配
- **未入股金额 = 投资费用总和 − 已投资金额**（仅当为正时显示，持平时隐藏）
- **利润 = 结余 × 股份占比**（结余为正才分）

## 六、数据模型（7 张表）

| 表 | 关键字段 | 说明 |
|---|---|---|
| users | username / password_hash / role | role = admin / viewer |
| revenue | amount_cents / date / account / platform / withdraw_cents | 金额按分存 |
| expense | amount_cents / date / category | 金额按分存 |
| investors | name / amount_cents / date | 股份由后端自动算，不存手动值 |
| investment_expenses | item_name / amount_cents | 费用项可自定义 |
| dicts | dict_type / name / is_active | platform / category / account；软删除 |
| logs | username / action / object_type / summary | 账变审计，只增不删改 |
